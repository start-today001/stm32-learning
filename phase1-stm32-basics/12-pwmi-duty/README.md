# 6-7 PWMI 模式测频率和占空比

## 硬件
- MCU: STM32F103C8T6
- **被测信号源**: PA0（复用推挽输出 `GPIO_Mode_AF_PP`，TIM2_CH1 输出 PWM，占空比 50%）
- **输入捕获**: PA6（上拉输入 `GPIO_Mode_IPU`，TIM3_CH1）
- **⚠️ 需要一根跳线把 PA0 和 PA6 接起来**
- OLED: SCL = PB8、SDA = PB9（软件模拟 I2C）

## 功能
- PWM 输出 **1kHz / 50% 占空比**，作为被测信号
- TIM3 用 **PWMI 模式**同时测量**频率**和**占空比**
- OLED 第 1 行 `Freq:xxxxxHZ`，第 2 行 `Duty:xx%`

## PWMI 模式的原理
一个周期里：

```
      ┌────────┐        ┌────────┐
      │        │        │        │
──────┘        └────────┘        └──────
      ↑        ↑        ↑
      上升沿   下降沿   下一个上升沿
      |←─高电平时间─→|
      |←────── 周期 ──────→|
```

- **上升沿 → 下一个上升沿** = 周期 → 通道1 捕获
- **上升沿 → 下降沿** = 高电平时间 → 通道2 捕获

用**两个通道同时捕获、共用同一个计数器**（从模式复位保证每个周期都从 0 开始数）：

| 通道 | 路径 | 边沿 | 捕获到的值 |
|---|---|---|---|
| 通道1（TI1） | `DirectTI` **直连** | 上升沿 | `CCR1` = 一个周期的计数 |
| 通道2（TI2） | `IndirectTI` **交叉** | 下降沿 | `CCR2` = 高电平时间的计数 |

计算结果：
```c
Freq = 1000000 / (CCR1 + 1);      // 捕获时基 1MHz
Duty = CCR2 * 100 / CCR1;         // 高电平 / 周期
```

**"交叉路径"是整个 PWMI 的关键**：通道2 用 `TIM_ICSelection_IndirectTI` 时，它的输入来自 **TI1 引脚**（也就是 PA6）—— 所以**同一个引脚、同一个信号**，被两个通道分别按上升沿和下降沿捕获。

## 代码结构（本项目复用了 6-6 拆出来的驱动）
```c
OLED_Init();
PWM_Init();               // 被测信号源
IC_Init();                // ① 时基 + 通道1（测周期）+ 从模式复位
IC_PWMI_Init();           // ② 只加通道2（PWMI：交叉路径 + 下降沿）
```

- `IC.c / IC.h` **与 6-6 完全相同**（逐字节一致）
- **调用顺序有要求**：`IC_PWMI_Init()` 只配置通道2，它依赖 `IC_Init()` 建好的 TIM3 时基与从模式设置，所以必须放在后面
- 这就是 6-6 / 6-7 解耦的价值：**同一份驱动，6-6 只用前一半，6-7 用完整的两半**
- 为什么不用 `TIM_PWMIConfig()`：它是"全包"函数，会**连通道1一起重配**，做不到"只给通道2加配置"。这里手写通道2，换来两个项目可以自由组合

## 显示上的一个细节（`OLED_ShowNum` 的位数必须和模板对齐）
```c
OLED_ShowString(2, 1, "Duty:00%");      // 模板写到 col8，其中 col8 = '%'
OLED_ShowNum(2, 6, IC_GetDuty(), 2);    // 只写 col6~col7 → '%' 保留 ✅
```
- `OLED_ShowNum` 会从指定列开始**连续写 `Length` 个字符**
- 最初这里写成了 `5`，会把 col8 的 `%` 覆盖掉 → 显示变成 `Duty:00050`（`%` 号消失）
- 第 1 行 `Freq:00000HZ` 用 `5` 位是**对的**：正好覆盖 5 个 `0`，把 `HZ` 保留下来
- ⚠️ 边界：占空比 = **100%** 时，2 位会显示成 `00` —— 因为 `OLED_ShowNum` 取的是十位和个位，都是 0。要完整显示得用 3 位并调整模板

## 学习点
- **PWMI = 一个定时器 + 两个捕获通道 + 一次搞定两个量**。硬件的"交叉路径"让同一个引脚同时接到两个通道
- 从模式复位在这里同样关键：计数器每个周期自动清零，两个 CCR 都直接对应"距本周期起点的计数"，不用软件做减法
- 输入捕获的三种典型用法，本仓库的演进路线：
  1. **测频率**（测周法）→ `11-input-capture`（6-6）
  2. **测频率 + 占空比**（PWMI）→ 本工程（6-7）
  3. **编码器接口**（硬件解码器，不走通道捕获）→ 6-8
- **性能视角**：从边沿捕获到算出结果，CPU 全程不参与，你只是读两个寄存器

## 已知边界（诚实标注）

### ⏳ 待验证：`+1` 到底是必需的还是多余的？（2026-09-23 记录，**待实机复测**）

`IC_GetFreq()`：
```c
return 1000000 / (TIM_GetCapture1(TIM3) + 1);
```
`IC.c` 与 `main.c` 里都留着一句原始观察：**「有误差1，+1看起来无误差」**。板子不在身边，无法实机复现，故只记录事实与推理、不下结论。

**已知事实**
1. 捕获时基 = 1MHz（1 计数 = 1µs），PWM = 1kHz（周期 1000µs）
2. 测周法下 `CCR1` 应等于"一个周期内的计数个数"
3. 整数除法会**截断**：`CCR1=999 → 1000000/1000 = 1000` ✅ ；`CCR1=1000 → 1000000/1001 = 999`（差 1）

**推论**：`+1` 是否正确，取决于硬件锁存到的 `CCR1` 是 999 还是 1000。

**模型仿真（PC 上按 RM0008 规则做的，非实机）**：在"先锁存 CCR1、再复位计数器"的时序模型下，1kHz 对应 `CCR1 = 1000` → 带 `+1` 得 999（差 1）、不带 `+1` 得 1000。即在该模型下 **`+1` 就是那 1 的来源**。

**⚠️ 关于这处观察的归属**：**本工程才是能测出这 1 误差的配置**（`PWM_SetCompare1(50)` = 50% 占空比）。而 6-6（`11-input-capture`）用的是 `PWM_SetCompare1(100)` 配 `ARR=99` → 按 PWM1 规则输出恒高、**零个跳变**，输入捕获根本不会触发，测不出来。所以那次观察极可能发生在**本工程**，注释后来被复制进了 6-6。

**复测清单（拿到板子后任选一条即可定论）**
1. **直接烧录本工程**，看第 1 行：显示 `01000` → 应去掉 `+1`；显示 `00999` → 保留 `+1`
2. 或加一行 `OLED_ShowNum(3, 1, TIM_GetCapture1(TIM3), 5);` 直接看**原始捕获值**
3. 或用逻辑分析仪 CH0 接 PA0（必须与板子共地）确认波形与占空比
