# 6-6 输入捕获模式测频率

## 硬件
- MCU: STM32F103C8T6
- **被测信号源**: PA0（复用推挽输出 `GPIO_Mode_AF_PP`，TIM2_CH1 输出 PWM）
- **输入捕获**: PA6（上拉输入 `GPIO_Mode_IPU`，TIM3_CH1）
- **⚠️ 需要一根跳线把 PA0 和 PA6 接起来** —— PWM 的输出直接接到捕获的输入
- OLED: SCL = PB8、SDA = PB9（软件模拟 I2C）

## 功能
- TIM2_CH1 输出 1kHz PWM，作为"被测信号"
- TIM3_CH1 用**输入捕获（测周法）**测量这个信号的频率
- OLED 第 1 行显示测量结果

## 被测信号参数（PWM.c）
- PSC = `720 - 1` → 72MHz ÷ 720 = 100kHz
- ARR = `100 - 1` → 100kHz ÷ 100 = **1kHz**（周期 1000µs）
- `PWM_SetPrescaler()` 封装了 `TIM_PrescalerConfig`，可以在运行时改 PWM 频率，用来观察测量值是否跟着变

## 输入捕获配置（IC.c）—— 测周法
- 捕获时钟：PSC = `72 - 1` → **1MHz → 1 个计数 = 1µs**
- ARR = `65536 - 1`（16 位满量程）：**测周法必需**，防止一个周期内计数器溢出
- 引脚 PA6 = TIM3_CH1，配 `GPIO_Mode_IPU`（上拉输入）
- 通道1：`TIM_Channel_1` + `TIM_ICPolarity_Rising`（上升沿）+ `TIM_ICSelection_DirectTI`（直连路径）
- `TIM_ICFilter = 0x0F`：最大输入滤波，抑制毛刺
- **从模式复位（测周法的核心）**：
  - `TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1)`：把 TI1FP1（通道1上升沿）选为触发源
  - `TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset)`：**每个上升沿自动把计数器清零**
  - 效果：CNT 永远只计"上一个上升沿到现在"→ `TIM_GetCapture1()` 拿到的**直接就是一个周期的计数值**
- 频率公式：`Freq = 捕获时基 / CCR1 = 1000000 / (CCR1 + 1)`

## 为什么叫"测周法"，以及它的固有限制
- **测周法**：先测一个周期的时间 T，再算 `F = 1/T`。低频时 T 大、量化误差占比小，所以**适合测中低频**（高频要改用"测频法"，即固定闸门时间内数脉冲个数）
- **量化误差恒为 ±1 个计数**，相对误差 = `1 / 捕获值`。捕获值越大，误差越小
- 提高捕获时钟（减小 PSC）能让捕获值变大、误差变小，**代价是可测最低频率上升**（16 位计数器能容纳的周期变短）：

| TIM3 PSC | 捕获时钟 | 1000Hz 时的捕获值 | 相对误差 | 可测最低频率 |
|---|---|---|---|---|
| `72-1`（本工程） | 1MHz | ~1000 | 0.1% | ~15Hz |
| `8-1` | 9MHz | ~9000 | 0.011% | ~137Hz |
| `1-1` | 72MHz | — | — | ❌ 溢出，测不了 |

## 学习点
- **输入捕获的本质**：外设硬件在指定边沿**自动**把 CNT 的值锁存进 CCR 寄存器 —— CPU 完全不参与，边沿再快也抓得住（这正是它比"软件轮询"强的地方）
- **从模式复位的巧妙**：不用软件做两次捕获再相减，硬件每个周期自动清零 → `CCR1` 直接就是周期值
- `TIM_ICSelection_DirectTI` / `IndirectTI` 就是**输入路径**的选择：**通道2 用 `IndirectTI` 时，它的输入来自 TI1 引脚**（交叉路径）—— 这就是同一个引脚能同时测频率和占空比的原因
- `TIM_PWMIConfig()` 是个"全包"函数：它会**自动同时配好 TI1 和 TI2**（一个上升沿 + 一个下降沿），所以它没法"只给通道2加配置"
- **本工程的代码结构做了 6-6 / 6-7 解耦**：`IC_Init()` 只做 6-6 测频率；6-7 的 PWMI（第二个通道，用 `IndirectTI` 配下降沿测占空比）独立在 `IC_PWMI_Init()` 里，按需调用

## 已知边界（诚实标注）

### ⏳ 待验证：`+1` 到底是必需的还是多余的？（2026-09-23 记录，**待实机复测**）

`IC_GetFreq()` 的公式：
```c
return 1000000 / (TIM_GetCapture1(TIM3) + 1);
```

`IC.c` 里原有注释写「有误差1，+1看起来无误差」，`main.c` 里也留了一句「有误差1，为什么有误差」。**但写这份 README 时板子不在身边，无法实机复现，所以只记录已知事实与推理，不下结论。**

**已知事实**
1. 捕获时基 = 1MHz（1 计数 = 1µs），被测 PWM = 1kHz（周期 1000µs）
2. 测周法下 `CCR1` 应等于"一个周期内的计数个数"
3. 整数除法 `1000000 / (CCR1 + 1)` 会**截断**：
   - `CCR1 = 999` → `1000000 / 1000 = 1000` ✅
   - `CCR1 = 1000` → `1000000 / 1001 = 999`（差 1）

**推论**：`+1` 是否正确，取决于硬件锁存到的 `CCR1` 到底是 999 还是 1000。

**模型仿真（在 PC 上按 RM0008 规则做的，非实机）**：在"先锁存 CCR1、再复位计数器"的时序模型下，1kHz 对应 `CCR1 = 1000` → 带 `+1` 得 999（差 1）、不带 `+1` 得 1000。即在该模型下 **`+1` 本身就是那 1 的来源**。

**⚠️ 同时存在一个未解释的矛盾**：`main.c` 用 `PWM_SetCompare1(100)` 配 `ARR = 100 - 1 = 99`。按 PWM1 模式规则（`CNT < CCR` 时输出高电平），`CCR = 100` 大于 `CNT` 的最大值 99 → 输出**恒为高（100% 占空比）→ 零个跳变 → 输入捕获永远不触发**，此时应显示 `00000` 而不是一个"差 1"的值。模型仿真也复现了这一点（5ms 内上升沿 0 次、下降沿 0 次）。
**因此「误差 1」那次观察，应该不是在 `CCR = 100` 的配置下取得的**（推测是早期 `CCR = 50` 时留下的注释）。

**复测清单（拿到板子后任选一条即可定论）**
1. 把 `PWM_SetCompare1(100)` 改成 **`50`**，烧录读数：显示 `1000` → 应去掉 `+1`；显示 `999` → 保留 `+1`
2. 或加一行 `OLED_ShowNum(2, 1, TIM_GetCapture1(TIM3), 5);` 直接看**原始捕获值**：`00999` 还是 `01000`
3. 或用逻辑分析仪 CH0 接 PA0（必须与板子共地）确认波形占空比 —— 100% 占空比是一条直线
